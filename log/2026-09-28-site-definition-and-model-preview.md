# 场地定义 Demo、视角过渡与模型轴测缩略图

日期：2026-09-28  
项目：House & Ground（PlayCanvas Engine + TypeScript + Vite）

## 本阶段目标

让用户基于自己的房屋模型定义前院、后院和左右侧院尺寸，通过四个固定视角查看场地，并在 Typology 区域展示当前基础模型的真实轴测缩略图。

## 已完成的功能

### 房屋模型与尺寸基准

- 加载 Rhino 导出的 GLB，保留原始模型层级和材质。
- 用户确认房屋实际外墙宽度为 **43 m**。模型原始宽度为 43000，使用 **0.001** 的比例换算。
- 当前矩形外墙包络为 **43 × 57 m**，包含后侧延伸部分；后院距离从完整包络计算，而不是从内退的 Back 墙面计算。
- 调整院子不会缩放房屋。模型源文件及备份保留。

### 场地定义

- 独立调整 Front yard、Back yard、Left clearance、Right clearance。
- 默认值分别为 5、7、2、2 m；支持 0–50 m，步长 0.1 m。
- 实时更新地面、场地总宽深、面积和尺寸标注。
- 前院使用一种材质，后院与左右侧院使用另一种材质。
- 空值或非法输入保留最后一次有效状态；零尺寸隐藏对应地面。

### 四个视角与动画

- Front / Back 使用带侧向角度的透视视角：侧向偏角 20°、俯视角 40°、垂直视场角 45°。
- Left / Right 保留原来的正交视角。
- 切换视角时执行约 **0.8 秒**的平滑绕行，同时过渡透视与正交投影。
- 连续点击从当前可见镜头位置继续移动，尺寸标签同步跟随。
- 尊重系统的减少动态效果设置；开启时直接切换。
- 修改场地尺寸或窗口大小会立即重新取景；此时不继续原有过渡。

### 面板与 Typology

面板顺序为：

1. Property size
2. 01 Typology
3. 02 Your perspective
4. 03 Yard dimensions

当前只有一个基础模型：**Fairy house**。

最初使用单选控件，随后改为静态轴测示意图。由于示意图不能准确表达当前模型，最终替换为根据实际 GLB 生成的缩略图。

### 根据模型生成轴测缩略图

- 新增独立的 `src/model-preview/` 模块，输入为引擎应用、模型实体及模型包围盒。
- 复用已经加载的模型网格与材质，不重复下载 GLB。
- 使用独立渲染层、临时正交摄像机和光源，仅拍摄房屋，不包含场地和尺寸标注。
- 根据包围盒自动取景，以 `(1, 1, 1)` 方向生成 **320 × 240** 轴测图。
- 只渲染一次，将结果编码为 PNG，并通过 Blob URL 显示在 Typology 卡片中。
- 生成后释放临时摄像机、光源、纹理和渲染目标；销毁模块时撤销图片 URL。
- 当前缓存为页面中该模型实例生命周期内的缓存，不是跨刷新持久缓存。
- 调整院子或切换主视角不会重新生成缩略图。生成失败时显示提示。

资源开销主要发生在首次生成时的一次离屏渲染、像素读取和图片编码。之后只显示静态图片，没有持续的缩略图渲染循环。

## 模块划分

| 路径 | 职责 |
| --- | --- |
| `src/house/` | GLB 加载、模型比例和外墙包络校准 |
| `src/site-definition/` | 场地尺寸、地面布局、尺寸控件和标注 |
| `src/camera/` | 视角管理、取景、投影和切换动画 |
| `src/model-preview/` | 根据实际模型生成轴测图片及管理临时资源 |
| `src/app/` | 视角预设、模块协调和资源生命周期 |
| `src/ui/panel.ts` | 面板结构及缩略图展示状态 |
| `src/main.ts` | 引擎初始化及各模块组装 |

相机模块与场地定义模块互不导入，由应用层协调。缩略图模块复用相机模块的纯取景函数，不依赖场地尺寸或面板 DOM。

## 验证结果

- 现有 **13 项回归测试通过**，覆盖场地布局、相机取景与过渡、投影一致性、协调和资源生命周期等。
- TypeScript 类型检查、ESLint 和生产构建通过。
- 浏览器确认缩略图采用真实模型的轮廓和材质，图片成功加载，尺寸为 320 × 240。
- 切换主视角和修改前院尺寸后，缩略图 URL 保持不变，确认复用缓存。
- 检查时浏览器没有控制台警告或错误。
- 生产构建仍有上游 `worker_threads` 外部化及较大 JS 包的提示，不影响构建成功。

缩略图本身通过实际浏览器验证；当前没有新增专门针对离屏 GPU 渲染的自动化测试。

## 当前范围与后续扩展

- 当前仅有 Fairy house；尚未实现多个模型之间的选择与切换流程。
- 更换 GLB 后需重新核对实际尺寸、坐标朝向和外墙包络。
- 当前场地采用矩形包络，尚不处理不规则地界、坡地或局部墙面凹进。
- 尚未加入尺寸持久化、房屋网格编辑或自由旋转相机。
- 后续增加多个 Typology 时，可复用缩略图模块，并由应用层管理模型切换及缓存失效。
